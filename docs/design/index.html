PeerDesk design mockups

Five screens, three directions, both themes. Open any file directly — no server, no npm.

Each page has the same control bar: switch direction with 1 2 3, theme with d / l. Combinations are addressable, e.g. machines.html?dir=slate&theme=light. These files are a decision aid and get deleted once a direction wins — nothing in the app imports them.

Directions

A — Aurora Glass
Aurora backdrop, translucent panels, teal-cyan accent splitting the difference between web's #00c896 and desktop's #26c6da. The only direction that depends on backdrop-filter.
B — Solid Slate
Same token discipline, zero glass. Opaque surfaces, firmer borders. No technical risk: works on any engine, costs nothing in the viewer.
C — Light Studio
Light-first, soft shadows instead of borders, indigo accent. Deliberately questions the teal as well — the only way to find out whether it is brand or inheritance.

What to decide

  • Does A earn its cost? Toggle between A and B on the same screen. If the difference is small, B gives you the same win with none of the risk.
  • Does the Tauri window support it? Open viewer.html inside npm run tauri dev and read the probe. WebKitGTK ships backdrop-filter prefixed; if both lines say NO, A is dead on desktop.
  • Is light mode a real product or a checkbox? Every direction has one. C is the only one designed for it first.
  • Is the accent teal, cyan or something else? The two apps disagree today. C proposes a third answer on purpose.
