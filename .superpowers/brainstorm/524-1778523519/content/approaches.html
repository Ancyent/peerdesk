PeerDesk — 3 Architecture Approaches

Each shapes the entire stack. Pick the one that fits your team and timeline.

A

Python-centric Stack

Agent: Python (mss + pynput + ffmpeg subprocess)
Signaling: FastAPI + WebSockets + Redis
Browser: TypeScript + WebRTC
Native client: Electron or PyQt
Relay: coturn (STUN/TURN)

Pros

  • Fastest to prototype
  • One language for backend + agent
  • Easy to extend

Cons

  • Python agent too slow for HD video
  • Hard to package cross-platform
  • Not production-grade for live streams
B

Rust Agent + Python Backend ⭐ Recommended

Agent: Rust (scrap + enigo + ffmpeg-next)
Signaling: FastAPI + WebSockets + Redis
Browser: TypeScript + WebRTC
Native client: Tauri (Rust + TypeScript)
Relay: coturn (STUN/TURN)

Pros

  • Rust agent: fast, safe, cross-platform
  • Python backend: easy to build & deploy
  • Tauri native client: very lightweight
  • Proven model (similar to RustDesk)

Cons

  • Two languages to maintain
  • Rust has a learning curve
C

Go Full-Stack

Agent: Go + CGo (screen capture via native libs)
Signaling: Go (Fiber + Redis)
Browser: TypeScript + WebRTC
Native client: Wails (Go + React)
Relay: coturn or Go custom relay

Pros

  • Single language: agent + backend
  • Single-binary deploy for server
  • Excellent concurrency model

Cons

  • CGo for screen capture is tricky
  • Less mature WebRTC libs vs Rust
  • Wails less battle-tested than Tauri

Common to all approaches

WebRTC (P2P + STUN/TURN fallback) • H.264/VP9 video encoding • WebSocket signaling • Docker/K8s deployment for SaaS
